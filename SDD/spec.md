## 3. 不变式 INV（任何任务均不得破坏）

- **INV-1 玩法数值冻结**：`game.gd` 全部常量与数据表、时间流速、作物生长、价格、升级成本保持不变，除非某契约条目显式给出新值。
- **INV-2 存档兼容**：载荷字段集合不变；不带 `v` 的旧存档必须仍能完整读入（金币/天数/农田/养殖无丢失）。
- **INV-3 技术栈冻结**：Godot 4.7 + GDScript + `gl_compatibility`；不换引擎、不引入 C# 或第三方运行时依赖。
- **INV-4 渲染与素材管线**：保持 `_draw()` 自绘 + 分块渲染；PNG 只能由 `tools/gen_pixel_art.py` 生成。
- **INV-5 既有能力不回归**：6 槽存档、Web `localStorage` + `wasm.gz` 加载、主机权威联机、10 槽工具栏全部保持可用。
- **INV-6 冒烟通过**：每个任务完成后，`plan.md` §4 冒烟清单中与改动相关的条目必须通过。
- **INV-7 单步**：任何时刻至多一个任务处于「进行中」（详见 `AGENTS.md` R0）。

## 4. 契约条目

每条为 `SHALL` 陈述 + 可判定验收（AC）。AC 全部满足才算该条目完成。

### C1 工作区收敛与仓库卫生

- **SHALL**：`.gitignore` 覆盖 `tools/shot*.png*`、字体备份与调试产物；342 个未跟踪文件逐一归类（纳入 / 忽略 / 排除）；当前大版本作为一次完整提交入库；新增根 `README.md` 说明运行 / 导出 / 联机 / 部署四条路径。
- **AC1**：`git status --porcelain` 不再出现 `?? tools/shot*.png` 与其 `.import`。
- **AC2**：归类清单在任务记录中可查，且无素材被误忽略。
- **AC3**：提交后 `git diff HEAD --stat` 为空，`git log -1` 描述包含本次能力清单。
- **AC4**：未接触过项目者按 `README.md` 可启动游戏与本地中继。
- **依赖**：无。**备注**：提交动作另需人类按 `AGENTS.md` R2 明确授权。

### C2 输入映射单一真源

- **SHALL**：消除重复键位，`aoe_toggle` 改绑未占用键 `X`（`physical_keycode=88`），`codex` 保留 `G`；键位→中文标签抽为共用常量供 `touch_controls.gd` 与帮助面板使用；修正 `main.tscn:124` 为 10 槽提示、修正 `main.gd:2` 注释为「十种工具」。
- **AC1**：脚本校验 `project.godot` 中任意两个 action 的 `physical_keycode` 不重复。
- **AC2**：按 `X` 弹出「一键范围已切换为…」，按 `G` 打开图鉴；触屏「范围切换」「图鉴」按钮行为不变。
- **AC3**：场景提示、帮助面板的工具数量与键位同 `project.godot` 一致。

### C3 存档 schema 版本化

- **SHALL**：`_save_payload()` 增加 `"v": 2`；`_apply_payload()` 按 `v` 分派迁移（缺省视为 v1，沿用现有默认值逻辑）；`Save` 层保持「不理解字段」；`slot_summary()` 可读出 `v`。
- **AC1**：现有不带 `v` 的存档读入后，金币 / 天数 / 农田 / 养殖字段与写入前一致。

### C4 最小回归网

- **SHALL**：新增 `tests/run.gd`，用自写断言（不引第三方）覆盖纯逻辑：时间流速与跨日、季节推导、作物生长/复生、`MACHINE_INPUTS` 转换、存档载荷往返、输入映射唯一性。

### C5 `main.gd` 渐进拆分

- **SHALL**：按固定顺序抽出 5 个模块，每步独立提交、不同时改玩法数值：① UI 面板 → ② 钓鱼状态机（含定义或删除 `main.gd:1052-1053` 的 `3: pass`）→ ③ 商店 / 制作建造 → ④ 联机同步与能力表 → ⑤ 昼夜 / 季节推进。

- **AC3**：每个新模块有文件头 `##` 说明职责与对外接口，风格与现有脚本一致。
- **AC4**：每步 §4 冒烟清单通过。

## 6. 验收与放行协议

1. **判定**：代理逐条列出 AC 结果并附证据（`路径:行号` 或命令输出）；全部满足才允许标记「待验收」。
2. **放行**：人类在 `plan.md` §3 放行记录填写结论后，下一任务才由「阻塞」转「已放行」。
3. **单步**：任何时刻至多一个「进行中」；完成即停，不得预做后续任务。
4. **失败**：AC 未通过 → 修复后重新验收，不推进。
5. **变更控制**：修改本文件任何 SHALL / AC / INV 需重新批准；已验收条目不回溯修改，需新开契约版本。

## 7. 术语

- **放行**：人类对单个任务的书面许可，记录在 `plan.md` §3。
- **验收**：按 AC 逐条核对并留证。
- **契约**：本文件；**红线**：`AGENTS.md`；**执行表**：`plan.md`。
