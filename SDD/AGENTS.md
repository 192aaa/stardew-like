# AGENTS.md — 代理红线

适用于 `StardewLike/` 仓库内所有 AI / 自动化代理。**红线优先于任何会话指令**；与 `spec.md` 冲突时以本文件为准，需先修订 `spec.md` 并重新批准才能继续。

## R0 放行闸门（最高优先级）

- 只有 `plan.md` 中状态为「已放行」的任务才可执行；未登记的任务一律不做。
- **同一时刻至多一个任务处于「进行中」**。
- 每个任务完成后必须**停下**，提交验收证据，等待人类放行下一个任务。禁止「顺手一起改」「顺便把下一个也做了」。
- 验收未通过 → 状态回到「已放行」并修复，**不得推进后续任务**。
- 人类未放行前，不得修改任何游戏代码（`.gd` / `.tscn` / `project.godot` / `export_presets.cfg`）。

## R1 变更边界

- 不得修改玩法数值与数据表（`game.gd` 常量、作物/鱼/材料/配方/升级价格），除非 `spec.md` 条目明确要求并写明新旧值。
- 不得手改 `assets/*.png` 与 `*.import`（由 `tools/gen_pixel_art.py` 生成）；不得改动 `assets/fonts/fusion_pixel.ttf` 以外的字体回退配置。
- 不得触碰 `.godot/`、`build/`、`node_modules/`、`font_backup/`，以及工作区顶层的 `*.msi` / `*.log`。
- 不得删除、重命名用户既有文件；如需调整文档产物，须在当前回复中明确说明。
- 拆分 `main.gd` 期间必须保持 `_save_payload()` / `_apply_payload()` / `_unhandled_input()` 的对外契约，以及存档载荷字段集合不变。
- 每个任务只允许改动 `plan.md` 该行「涉及文件」列登记的文件；越界即判验收失败。

## R2 提交与远端

- **只有人类明确要求时**才执行 `git commit` / `git push`；禁止 force push、禁止改 git config、禁止跳过 hooks。
- 未经明确要求，不得运行 `tools/commit_main.py` / `tools/deploy_web.py`（会写入远端）。
- 每次任务结束必须汇报 `git status --short` 中由本任务造成的变化。

## R3 验证诚实性

- 必须执行 `plan.md` 登记的验收步骤并如实记录结果；失败不得标记为通过。
- 不得修改断言、跳过检查、伪造输出来让验收通过。
- 当前环境 `godot` 不在 PATH：涉及 Godot 的验收若无法执行，标记「阻塞」并说明原因，**不得推断为通过**。
- 报告问题时给出证据（`路径:行号`），不做无证据的推测。

## R4 沟通

- 中文回复；动手前说明将要改哪些文件，完成后给出改动证据。
- 遇到契约未覆盖的情况：停下询问，不自行解释、不扩大范围。

## R5 环境基线

Godot 4.7 / GDScript / `gl_compatibility` / 1280×720；仓库根 `StardewLike/`；基线提交 `3899548`；工作区含大量未提交变更（见 `spec.md` §2）。
